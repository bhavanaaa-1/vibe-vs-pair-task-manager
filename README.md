# Vibe vs. Pair Challenge

This challenge involves building the same Task Manager application twice to compare two distinct AI-assisted development workflows: **Vibe Coding** (using generative UI/app tools) and **AI Pair Programming** (using editor-integrated assistants).

## The App You Are Building

The same Task Manager application was built using both approaches. Both versions implement the exact required feature set from [app-spec.md](./app-spec.md):

- Add a task
- Mark a task as complete
- Filter tasks by All / Active / Completed
- Display the number of tasks remaining

No backend, authentication, persistence, routing, or additional features were added.

## Your Folders

- `/vibe-version`: Version built using Google AI Studio Build.
- `/pair-version`: Version built using Cursor.

## Live Deployments

- Vibe version: https://vibe-vs-pair-task-manager.vercel.app/
- Pair version: https://vibe-vs-pair-task-manager-rjsh.vercel.app/

## Comparison Table

| Dimension | Vibe Version | Pair Version |
| :--- | :--- | :--- |
| **Speed** | Google AI Studio Build generated the complete working application in approximately **2 minutes 15 seconds** from one prompt. | Cursor version took approximately **45 minutes** because the application was developed incrementally with AI assistance and manual review. |
| **Control** | The complete application structure and implementation were generated by the tool, giving less control over individual implementation decisions during generation. | Cursor allowed me to control the implementation step by step and accept, modify, or revert suggestions. One broad suggestion generated duplicate state/handler logic and was reverted. |
| **Code Quality** | Generated a structured React + TypeScript + Vite project with a polished initial UI. The main application logic was concentrated in `App.tsx`. | Produced a smaller React + Vite project with the main application logic in `App.jsx`. Cursor occasionally produced overly broad suggestions that required review and cleanup. |
| **Explainability** | I had to inspect some generated code to understand implementation decisions that I had not made myself. | The application was built incrementally, so the purpose of the state and handlers was easier to follow and explain. |
| **Editability** | The generated application worked immediately, but modifying generated logic required understanding the structure produced by the tool. | Individual pieces could be changed directly while developing, and Cursor could assist with targeted modifications. This made iterative changes easier to control. |

## Build Observations

### Vibe Version

- **Tool:** Google AI Studio Build
- **Measured generation time:** approximately **2 minutes 15 seconds**
- The complete application was generated from one natural-language prompt.
- The generated project contained **11 files** across its generated project structure.
- The main React component was `App.tsx`.
- The generated project used React, TypeScript, and Vite.
- No manual code edits were made to the generated implementation before export.
- All required functionality was tested successfully before deployment.
- The exported project also ran successfully locally before being deployed.

### Pair Version

- **Tool:** Cursor
- **Build time:** approximately **45 minutes**
- The application was developed incrementally using Cursor's inline AI assistance.
- The main application component was `App.jsx`.
- The `src` folder contains `App.jsx`, `index.css`, and `main.jsx`.
- The Pair version contains **8 project files**, excluding `node_modules`.
- Cursor suggestions were reviewed and accepted, modified, or reverted during development.
- One broad suggestion generated duplicate state and handler logic. I noticed the duplication and reverted the suggestion.
- Cursor also assisted with the checkbox implementation, including preventing the checkbox click from triggering the task-row click twice.
- The completed application was tested locally and deployed successfully.

## When I Would Use Each Tool

- **Vibe coding tool:** I would use Google AI Studio Build for rapid prototypes and simple applications where getting a working version quickly is the main priority. It produced the complete Task Manager in approximately **2 minutes 15 seconds**.
- **AI pair programming:** I would use Cursor for projects that I expect to understand, modify, and maintain over time because I can control individual implementation decisions and review AI suggestions while coding.
